这是 `v0.2.0` 公开 OSS 发行版（V2 产品阶段）。真实模型证据仅针对
DeepSeek `deepseek-flash` 上有记录的流程与发布源码树，不构成普遍模型/Provider 验收。数字自我会话、Living Object、对象授权、版本化动作、事件历史、
Derive、来源链、审计、幂等、邀请与 Derive Link、Handoff、Personal AI 会话、
Trust Kernel、AI 提议/确认、PAT、本人导出、Capability Broker、五项首发能力、
Open API、TypeScript SDK、独立 `content.structure` Provider、响应签名传输、
TLS 校验、HMAC 密钥轮换与模型预算控制已实现。这是可自托管的 OSS MVP，不是生产平台。

## 账号发现与隐私默认值

- 账号发现**默认开启**：已登录用户可以通过精确 handle 或显示名子串找到另一个账号，并发送好友请求。发现不暴露邮箱、账号状态或未过滤的目录；它要求登录、按查询限定并限流，可在好友搜索对话框中关闭。
- 关闭发现不会抹除账号的存在：精确 handle 查询仍可发现它，仍可发送未经请求的好友请求。屏蔽与对象权限仍然生效。将发现改为严格主动开启、并在设置中提供入口，属于 V3 工作。

## v0.2.0 中的自由世界

- 自由世界的内容是声明式数据：创建者定义存在种类、存在、关系、一次性规则，以及可选的组合体验。内容不属于任何固定产品分类。
- 体验是由已注册能力组成的有界树：布局、文字、可绘制任意 SVG 路径的向量空间、重复集合、数据表、字段编辑、进度条、按钮、选择、上传的图像/视频、上传或程序化音频，以及带摄像机移动、重力与碰撞的真实三维场景。可复用行为覆盖状态修改、数值转移与事件音效。`GET /api/v1/world-capabilities` 公开同一份能力目录，产品的能力面板与生成的表单都由它驱动。
- 新增能力是模块变更（Go 校验/执行模块 + 客户端渲染器与描述），不是世界协议变更。所有已注册能力都可被任意世界复用。经典场景、舞台、卡片与时间线仍是同一世界的可选视图；世界不会因为体验变化而被转换成另一种对象类型。
- 服务器解释所有值。它不执行用户代码，不加载外部 URL、字体或脚本，也不开放网络访问。上传的图像、视频、音频与 GLB 模型按内容验证，由本服务器在世界自身权限下提供，并用不透明 ID 引用。图像会解码并重新编码；GLB 只允许内嵌 BIN 块。三维渲染、摄像机、重力与简单碰撞在浏览器中运行（three.js）；物理变换是临时的，只有行为驱动的状态变化会被持久化。字符串只作为文本渲染；矢量路径使用受限的绘图命令语法；所有值都有界。
- 边界：静态视图节点 64 个、深度 8、每节点子节点 24、行为 24 个、每行为动作 8 个、每节点 props 4 KiB（scene3d 与 custom 为 12 KiB，audio 为 8 KiB）、整个体验 48 KiB、展开渲染实例 400 个，并继续受 64 KiB 对象状态上限约束。行为一次性执行，不连锁。
- `set_experience` 与 `invoke_behavior` 需要 `contribute`；无读权限仍返回 404。每次修改继续走既有行锁、`expected_version`、幂等、事件与审计路径。
- 以 `structure` 衍生时复制体验，并重映射能力 props 的已声明引用字段与 `{{entity.<id>...}}` 模板 token 中的种类/实体 UUID；本地视图/行为 ID、字段键与普通文本保持稳定。子世界独立并通过重新校验；父世界不变。衍生粒度仍是整个对象：尚不支持按实体、字段或单个能力衍生。
- 行为改变一个存在时，会为该存在运行一次旧规则；语义与 `set_node_field` / `set_node_status` / `touch_node` 一致。规则不连锁，旧规则也不能反过来调用 behaviors。
- 冻结的 `object.propose_change` 能力保持已发布的操作集合。体验编辑是人类产品路径。绑定对象的 AI 仍可提议既有的结构动作，未绑定世界的 AI 可通过 `world.create` 提议完整世界；二者都需人类批准。**通过该冻结 schema 生成丰富的 AI 体验文档目前尚不可用**，且 8 KiB 模型输出上限是这类工作的真实约束。
- 仍需如实说明的能力边界：首版模块没有通用的运动/环境/地平线模块（经典场景仍负责这些效果）；`core.space` 自带受限的渐变/纯色/无背景，而不是独立背景能力；组合条件与 `visible_when` 可由 API 编写，但可视化编辑器只编辑单个简单条件；`$event.value` 可供 API 集成使用，但当前产品控件不会提供事件值；能力描述带版本号，已存储的视图节点却只引用能力 ID、没有内嵌版本；匿名 Explore 预览仍是元数据摘要，不渲染组合体验。新增这些能力应作为新模块或明确协议扩展，而不是新增固定世界分类。
- 未绑定世界上下文的 Personal AI 可以提出一个完整世界。提议在存储前会经过校验；在人类批准五分钟确认之前，不会创建任何对象。
- Fixture 输出是确定性演示数据，并始终带有标记；真实模型输出是独立、由部署者配置的模式，不能由 Fixture 行为推定。


## v0.2.0 中的多形式世界

- 创建不再是选择类型。用户只描述想创造什么；Personal AI 写出一份紧凑的世界种子，服务器工坊把它展开成真实可运行的内容与体验。普通用户不需要知道能力、字段、运行时或 JSON。
- 一个世界可以同时拥有多种通用表面，共享同一份内容、状态、变量、权限、版本与来源链：
  - `core.live`：时间驱动的 2D 世界。没有化身时是真正播放的动态画面（时间线、粒子、运动）；有化身时可走动、碰撞、接近互动；有目标时可收集、得分、到达或生存，并有胜负与重开。
  - `core.story`：篇章是真实存在，选择是真实关系，阅读位置是共享变量；可阅读、选择、续写、改写、衍生。
  - `core.workspace`：以真实存在和字段为数据，可编辑、增行、状态切换、执行行为并查看汇总；是可实际使用的工作环境。
  - `core.space`：静态可视关系空间。
  - `core.media`：真实上传的图像或视频，支持适配、控件、循环、静音/自动播放意图，以及由世界变量控制的显示与播放。
  - `core.audio`：上传的环境音或程序化音调，加上由世界变量变化驱动的有界事件音效。浏览器要求用户手势后才开始播放声音。
  - `core.scene3d`：把同一批存在放进真实三维场景。种类选择基础形体或上传的 GLB；摄像机可环绕或跟随角色；重力、跳跃与盒/球碰撞在客户端运行；点击存在会运行其行为。
  - `core.custom`：受控声明式表面。AI 可用形体、文字、输入、按键、拖动、条件、动作、时间线与程序化音调定义固定表面未覆盖的新形式；服务器解释，客户端渲染，不执行用户代码。
  - `core.tabs`：把任意表面组合进同一个世界；标签来自世界内容，不是产品分类。音频层可以放在标签之外，从而在切换表面时持续播放。
- 创建时 kinds/nodes 可使用本地 `ref`；服务器铸造 UUID 后重映射体验引用，因此创建时即可带完整体验。
- 世界共享变量（≤128 个、总计 ≤8 KiB）保存游戏分数、小说阅读位置、工作台状态等；变量进入版本、事件、审计、快照与衍生。
- 绑定世界的 AI 用 `world.reimagine` 提出内容/表现/行为的合并；服务器用 `worldseed.Reshape` 合并当前世界，生成 `reshape_world` 提议；人类应用后原子替换。内容按名称合并，保留既有 ID、行为、任意形体与实体互动；体验外壳按目标表面重建。
- 复杂世界可以多轮扩展：每次 AI 回合受 8 KiB 输出限制，但可以持续追加东西、章节、表面与自定义节点，直到世界状态/体验的硬上限。
- 限制（如实）：声明式 2D 与 3D 表面；上传的图像/视频/音频/GLB 模型；客户端简单物理；不含网络访问、任意代码、多人实时同步或任意视频生成。上传有单文件上限（图像 8 MiB、音频 16 MiB、GLB 32 MiB、视频 40 MiB）、每世界上限（40 个文件 / 64 MiB）与每用户每 UTC 日上限（256 MiB）。自定义表面最多 40 个节点、12 KiB props，整个体验 48 KiB，对象状态 64 KiB，变量 128 个/8 KiB；一次 AI 输出 8 KiB，一次创建的确认内容 12 KiB。媒体字节永远不会进入对象状态。超出的部分不会被假装实现；新的媒体或生成能力仍需经过验证的通用模块，而不是每世界专属页面。
- 视频与音频按原字节保存；与图像不同，它们不会被重新编码，因此上传带位置/设备元数据的媒体前应先自行清除。产品不声称对这些容器做元数据移除。
- `core.custom` 是可组合的安全扩展路径，不是“所有媒介已实现”的声明；它创造固定表面未覆盖的形式，上传媒体、音频与三维由各自的通用模块提供。
- Fixture 仍是确定性演示，始终标注；真实模型验收需要单独授权与配置。

## v0.1.0 已实现

- 本地注册、登录、会话轮换、退出与会话绑定 CSRF。
- 注册时同事务创建 Personal AI 档案与空私人上下文。
- 协作与互动两种 Living Object。
- 依据活跃成员记录进行所有者/成员授权；无 `read` 一律 404。
- 显式 `expected_version`、行锁与 `409 version_conflict`。
- 追加写对象事件与 `seq` 游标。
- 从当前版本或不可变历史快照衍生。
- 独立子对象状态、清单/选项 ID 重生成、投票清零与 `derivation_edges` 来源。
- 来源链深度上限与不可读祖先/后代隐私裁剪。
- 审计同事务、创建/动作/衍生的幂等与软删除。
- 一次性邀请/Derive Link：权限上限、有效期、次数、撤销、原子接受，以及重邀时权限精确覆盖。
- 成员移除与所有者保护；移除后立即 404。
- Handoff 投影：32 KiB 预算、L1–L4 裁剪、固定事件摘要字段、来源标注，且不含私人 AI 数据。
- 私人 Personal AI 会话与消息、Fixture/Real 模式、一次回合一次模型调用、结构化动作解析与模型计量。
- Trust Kernel 委托求交、立即撤销、确认创建/批准/拒绝/过期、规范化 payload 哈希与版本重校验。
- AI 状态修改提议与人类应用/拒绝/过期；AI 衍生只能通过五分钟人工确认。
- 个人访问令牌（封闭 scopes，Cookie-only 端点排除）。
- 仅本人 `/me/export`，每小时一次。
- 双语参考世界：私人上下文、档案、委托、邀请、Handoff 预览、AI 会话、提议、确认、令牌、导出。
- Capability Broker：配置注册、启动 Schema 校验、数据库同步、幂等、限流/并发与调用审计。
- 五项冻结能力：`object.read`、`object.context`、`object.propose_change`、`object.derive`、`content.structure`。
- PAT 可用的能力列表/详情/调用与 invocation 查询 Open API，以及 OpenAPI 3.1 与零依赖 TypeScript SDK。
- 独立、仅标准库的参考 Provider：内部网络 HTTP+HMAC、重放防护、SSRF 防御与输出校验。
- `http_hmac_v2` 响应签名绑定请求时间戳、Invocation、HTTP 状态与响应体精确哈希；未签名或被篡改的响应视为未知结果，输出绝不入库。
- TLS 校验（最低 TLS 1.2）、私有 CA 与双向 TLS，以及对明文 Provider URL 配置 TLS 的启动拒绝。
- 有界 HMAC 密钥轮换：当前密钥与带 RFC3339 截止时间的旧密钥；过期、重复或相同旧密钥按失败关闭。
- 单次模型输入/输出上限、每用户每日预算、部署级每日硬上限、运维停止开关、调用前拒绝、审计与重启后从 `model_invocations` 重新计数。
- 阻断式 Chromium + Firefox Playwright 套件，两个独立用户、真实 PostgreSQL/API，以及 390 px 移动项目。

## 产品限制

- 仅单实例；不支持横向扩展。
- 每个部署只激活一个模型适配器。Provider 接口与部署配置是厂商中立的，但更换模型仍需修改部署配置，不能同时运行多个 Provider。
- 不支持同时协同编辑。对象工作区使用认证 SSE 刷新信号并带轮询降级；过期写入返回版本冲突，而不是静默覆盖。
- 好友、直接消息、公开世界与公开衍生均限于同一实例；不支持跨实例联邦或公开导入。
- `v0.2.0` 不发邮件、不做密码找回、不做 OAuth、不验证邮箱、不提供账号删除。
- `v0.2.0` 不提供独立产品官网或原生移动客户端。
- Fixture 是确定性演示输出，不得表述为真实 AI。
- Compose 是参考部署，不是生产编排。
- 默认 Compose 栈在内部明文 `capnet` 上运行 Provider，但响应已签名。TLS 与双向 TLS 已实现、已测试并可通过配置启用，默认参考栈未启用。公网 Provider 必须使用 HTTPS 与 `http_hmac_v2`。
- 旧 `http_hmac` 传输不签名响应，仅为内部兼容保留。
- 模型预算使用单实例内存计数，在每个 UTC 日首次调用时从 `model_invocations` 重新载入。实际尝试 Provider 调用前会写入持久预占行并计入预算；进程崩溃、业务回滚或最终更新失败都不会漏记可能产生费用的调用。多个 app 副本仍不共享内存并发/计数状态；持久行防止漏记费用，但不提供多副本协调。
- 历史对象状态可在 `GET /api/v1/objects/{id}/versions/{version}` 读取，但仅当调用者当前仍持有读取权限；撤销立即生效。
- GitHub Dependency Review 在公开 Pull Request 上运行，是发布门禁的一部分；要求的检查同时覆盖 govulncheck、gitleaks、npm audit 与 License。
- 不发布预构建容器镜像；Compose 从源码构建。
- `v0.2.0` 发行资产由公开发布工作流生成 GitHub 构建来源证明；请使用 `gh attestation verify` 针对本仓库、Tag 与工作流验签。

## 数据限制

- `v0.2.0` 为 36 表 Schema（版本 11）。迁移 4–11 追加在已发布的 `v0.1.0` 22 表 Schema 之上：社交/公开/场景表、账号可发现性与用户私人世界布局状态、自由世界与世界媒体资源、AI 消息提示与批准链接；旧迁移不被重写。
- 对象状态上限 64 KiB；`shared_context` 上限 8 KiB。
- AI 提议 input 存储上限 64 KiB。提议创建与应用适用不同限额：应用受 64 KiB 状态约束；`object.state_changed` 事件 payload 上限为 132,352 字节，其他事件仍为 96 KiB。
- 20,000 是 Unicode **code point** 上限，不是字节保证。按负责人 V1 解释，20,000 code point 的正文上限与 65,536 字节的完整状态上限**同时生效**。能装入状态的 20,000 个 ASCII、中文或混合字符可以应用；20,000 个四字节 Emoji（约 80,000 字节）超出状态上限，返回 `413 payload_too_large` 且无副作用。20,001 个 ASCII 即使字节数低于 64 KiB，也返回 `400 invalid_request`。
- 大小限额按 PostgreSQL `jsonb` 文本计量；包含 `&`、`<`、`>` 或 U+2028/U+2029 的合法正文不会因 JSON HTML 转义而被错误拒绝。
- 能力输入上限 64 KiB；外部 Provider 的 HTTP 正文上限为该输入加精确的 126 字节签名信封。
- 审计 metadata 上限 4 KiB，拒绝嵌套值。
- 幂等响应上限 256 KiB。
- 备份为手工逻辑转储，不做 PITR。
- 删除 `dw_pgdata` 卷会销毁本地数据。

## 诚实状态

不声称生产就绪、安全认证、用户采用、Star、下载量或融资。`v0.2.0` 是 V2 产品阶段发行版。真实模型证据（DeepSeek `deepseek-flash`）覆盖发布源码树上的世界创建、连续修改与衍生等已记录流程，具体版本与范围见[发行说明](release-notes.md)；它不是对所有模型或 Provider 的普遍验收。
