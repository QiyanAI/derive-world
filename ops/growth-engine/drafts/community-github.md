# Discussion: what should a derived world keep from its source?

Derive World records lineage for derived objects: a child is independent, and later edits to the parent do not propagate. [[fact:lineage]]

I would like to hear how other builders think about this. When you derive a world, what should stay, what should reset, and what should be explicitly re-approved? The product currently derives at the whole-object level; per-entity derivation is not implemented. [[fact:what-it-is]]

If you try it, please use Fixture mode first and label any screenshots as Fixture — it is deterministic demo output, not real AI. [[fact:fixture-not-real-ai]]

This is a genuine question, not a launch post. Answer only if you have something concrete to add.

## Facts used

- `what-it-is` — Derive World is an open-source foundation for Living Objects: shared, versioned objects that people and their Personal AI can read, contribute to, derive from, and trace through an explicit lineage.
- `lineage` — Derive creates an independent child from an immutable snapshot of the source; later edits to the parent do not propagate and the ancestry is recorded.
- `fixture-not-real-ai` — Fixture mode is a deterministic demo: it calls no model and is not real AI.
